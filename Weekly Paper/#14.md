# 📘 Weekly Paper — Docker & Kubernetes 핵심 개념 정리

## 1. Docker 이미지 vs 컨테이너

Docker를 처음 접하면 가장 헷갈리는 개념이 바로 **이미지(Image)**와 **컨테이너(Container)**입니다.

### ✅ Docker Image란?

* 실행 가능한 애플리케이션 환경을 **정적으로 저장한 템플릿**
* 코드, 라이브러리, 의존성, 실행 환경까지 포함
* 변경되지 않는 **불변(immutable)** 구조

👉 쉽게 말하면

> **"설계도" 또는 "스냅샷"**

예:

* Node.js 앱 + npm 패키지 + OS 환경 → 하나의 이미지

---

### ✅ Docker Container란?

* 이미지를 기반으로 실행된 **실제 프로세스**
* 격리된 환경에서 실행됨 (namespace + cgroups)
* 실행 중에는 상태 변경 가능

👉 쉽게 말하면

> **"설계도를 기반으로 실제 지어진 건물"**

---

### 🔥 핵심 차이 정리

| 구분 | Image        | Container  |
| -- | ------------ | ---------- |
| 개념 | 실행 환경 템플릿    | 실행 중인 인스턴스 |
| 상태 | 불변           | 가변         |
| 역할 | 생성 기반        | 실행         |
| 예시 | `.tar` 같은 파일 | 실행 중인 앱    |

---

### 💡 한 줄 정리

> **Image는 "정적인 실행 환경", Container는 "실행된 결과물"이다.**

---

## 2. Docker Compose vs Dockerfile

Docker를 쓰다 보면 단일 컨테이너를 넘어
여러 서비스를 함께 관리해야 하는 상황이 발생합니다.

이때 등장하는 것이 **Docker Compose**입니다.

---

### ✅ Dockerfile이란?

* 하나의 이미지를 만들기 위한 **설계 파일**
* build 과정 정의

예:

```dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]
```

👉 역할

> **"이미지를 만드는 레시피"**

---

### ✅ Docker Compose란?

* 여러 컨테이너를 **한 번에 정의하고 실행하는 도구**
* `docker-compose.yml`로 관리

예:

```yaml
version: '3'
services:
  web:
    build: .
    ports:
      - "3000:3000"
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: example
```

👉 역할

> **"여러 컨테이너를 하나의 시스템처럼 관리"**

---

### 🔥 언제 유용한가?

Docker Compose는 아래 상황에서 특히 강력함:

* 웹 서버 + DB + 캐시 (Redis) 같이 **멀티 컨테이너 구조**
* 로컬 개발 환경을 빠르게 세팅할 때
* 팀원 간 동일한 환경 공유

---

### 🔥 핵심 차이

| 구분 | Dockerfile | Docker Compose        |
| -- | ---------- | --------------------- |
| 목적 | 이미지 빌드     | 컨테이너 실행/관리            |
| 대상 | 단일 컨테이너    | 다중 컨테이너               |
| 파일 | Dockerfile | docker-compose.yml    |
| 역할 | build      | orchestration (간단 수준) |

---

### 💡 한 줄 정리

> **Dockerfile은 "이미지를 만드는 도구", Compose는 "여러 컨테이너를 관리하는 도구"**

---

## 3. Kubernetes 기본 개념 & Docker와의 관계

컨테이너가 많아지면 관리가 어려워집니다.
이 문제를 해결하기 위해 등장한 것이 **Kubernetes**입니다.

---

### ✅ Kubernetes란?

* 컨테이너를 자동으로 배포, 확장, 관리하는 **오케스트레이션 시스템**
* Google에서 시작 → CNCF 프로젝트

👉 역할

> **"컨테이너 운영 자동화 플랫폼"**

---

### ✅ Kubernetes의 핵심 개념

#### 1. Pod

* 하나 이상의 컨테이너를 묶는 최소 단위
* 보통 1 Pod = 1 Container

#### 2. Node

* Pod가 실행되는 물리/가상 서버

#### 3. Cluster

* 여러 Node를 묶은 시스템

#### 4. Deployment

* Pod의 개수, 업데이트 전략 등을 관리

---

### 🔥 Kubernetes가 해결하는 문제

* 컨테이너 자동 배포
* 자동 스케일링 (트래픽 증가 대응)
* 장애 발생 시 자동 복구
* 롤링 업데이트

---

### ✅ Docker와의 관계

| 구분 | Docker     | Kubernetes |
| -- | ---------- | ---------- |
| 역할 | 컨테이너 생성/실행 | 컨테이너 관리/운영 |
| 초점 | 단일 실행 환경   | 대규모 운영     |
| 관계 | 컨테이너 기술    | 오케스트레이션    |

👉 구조적으로 보면:

```
Docker → 컨테이너 생성
Kubernetes → 컨테이너를 여러 개 관리
```

---

### 💡 한 줄 정리

> **Docker는 "컨테이너를 만드는 도구", Kubernetes는 "컨테이너를 운영하는 시스템"**

---

## 🚀 전체 흐름 정리

```
Dockerfile → Image 생성 → Container 실행
                        ↓
               Docker Compose (여러 개 관리)
                        ↓
               Kubernetes (대규모 운영)
```

---

## 🧠 최종 핵심 요약

* **Image vs Container**
  → 설계도 vs 실행체

* **Dockerfile vs Compose**
  → 빌드 vs 실행 관리

* **Docker vs Kubernetes**
  → 생성 vs 운영

---

## ✍️ 마무리

Docker는 **개발 환경 표준화**를 가능하게 만들었고,
Kubernetes는 이를 **대규모 서비스 운영 수준으로 확장**시켰다.

이 둘을 함께 이해하는 것이
현대 백엔드/AI 엔지니어의 필수 역량이라고 볼 수 있다.
